# limpa-rs v0.1.0-rc.2

Second public release candidate. The numerical core is unchanged from v0.1.0-rc.1; this release updates the supported Python version and dependencies, carries upstream citations into results, and is the first limpa-rs release archived on Zenodo with a DOI.

## Changes since v0.1.0-rc.1

- **Python >=3.14 is now required** (rc.1 accepted >=3.11).
- Rust dependencies are pinned exactly: nalgebra 0.35.0 (was 0.34) and rayon 1.12.0. Rust and R reference-equivalence checks pass with these versions.
- Python, R and Rust dependency pins are enforced in CI, with a seven-day age delay for new releases, security audits and the shared Deliverome dependency guard.
- Security floors: certifi >=2026.10.19 and pip >=26.2.2 (eMudhra CA compromise), filelock 4.2.4 and setuptools 84.2.0 (known CVEs). uv >=0.13.4 is required to work on the project.
- Results carry the upstream LIMPA citations and the AI-assistance disclosure; see CREDITS.md.
- Zenodo metadata (.zenodo.json) and a complete CITATION.cff author record.

## Installation

Install the matching wheel from this release, or build the source distribution with Rust installed. Python >=3.14 and R 4.6.x are required; macOS and Linux are supported.

```sh
python -m pip install /path/to/limpa_rs-0.1.0rc2-<wheel-tags>.whl
python -m limpa_rs setup-r
python -m limpa_rs doctor
python -m limpa_rs validate
```

```python
from limpa_rs import run_limpa_spectronaut
result = run_limpa_spectronaut("NormalReport.tsv", cores=4, seed=141)
```

LIMPA is pinned to 1.4.2, source commit d9ad5218207434cfcbe080328db5e79d39a1623a. R continues to provide filtering, DPC/hyperparameter estimation, starting values, and downstream differential analysis. This is a hybrid implementation, not a complete R-free port.

## Readiness and measured limits

This release remains a **release candidate**, not a production-validated 384-sample replacement. The actual ~384-sample Astral cohort has not been supplied or validated. Full-cohort numerical equivalence, >=20x speedup and the 15-minute target therefore remain open acceptance criteria.

The real three-run Astral export (11,010 proteins) passed the fixed 0.001 log2/SE tolerance; maximum log2 difference was 6.75e-8. Its measured speedup was 10.75x. A workload expanded from those three runs to 384 columns took 64.799 seconds for matrix-to-protein processing, but is not an actual 384-sample experiment. Large matched subset speedups are not full-cohort speed measurements. See BENCHMARKS.md for timing boundaries and failures retained in the record.

Synthetic validation covers missingness, singleton/fallback cases, IDs, ordering, annotations, standard errors, DE calls, compact-matrix input, and one/four Rust threads. Invalid or incomplete package results are rejected, and successful results are published atomically. A failed run must not be interpreted as a completed analysis.
